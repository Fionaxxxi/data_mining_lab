# 实验三：实验过程中遇到的问题及解决办法

> 覆盖景区：黄山 / 九寨沟 / 张家界
> 本文件记录本次实验（数据采集 → 路线解析 → 时间层级 → 官方/游客对比）中实际遇到的主要问题、原因分析与解决办法。

---

## 一、数据采集阶段

### 问题 1：黄山风景区官网（cnhuangshan.com）被反爬拦截
- **现象**：requests 直接请求返回 200，但抓取正文时连接超时；随后多次请求均超时或返回异常；黄山市政府站（huangshan.gov.cn）返回 HTTP 412（反爬）。
- **原因分析**：
  1. 黄山官网采用较严格的访问控制（WAF / 限流），对高频、非浏览器 UA 的请求直接限流或断开；
  2. 首次探测能访问可能只是瞬时放行，后续请求因特征被识别而拦截；
  3. 政府站 412 多为安全网关对疑似爬虫请求的校验响应。
- **解决办法**：
  1. 放弃直接抓取 cnhuangshan.com，改用其管理机构的**权威公开页面**；
  2. 通过搜索定位到**黄山风景区管理委员会官网**“黄山一日游”线路页面（hsgwh.huangshan.gov.cn/lyfw/xltj/9135988.html），用 web_fetch 完整获取 5 条官方线路文本；
  3. 将其中“线路一”作为黄山官方路线样本，并在报告中标注真实来源 URL。
- **经验**：官网被反爬时，优先转向该景区的**管委会/政府权威页面**，比反复对抗反爬更可靠且来源更权威。

### 问题 2：马蜂窝等游记社区站点无法稳定采集
- **现象**：马蜂窝返回 202（反爬验证页），百度百科返回 403。
- **原因分析**：社区类站点普遍部署反爬验证（JS 校验、验证码、IP 风控），纯 requests 无法通过。
- **解决办法**：
  1. 游记类叙述改用**教师提供的数据集**（IndustryCorpus2 住宿餐饮酒店中文语料）按旅游关键词过滤抽样，作为游客叙述补充；
  2. 官方信息以可稳定访问的九寨沟官网（jiuzhai.com）、张家界市政府（zjj.gov.cn）、红网张家界（zjj.rednet.cn）为爬虫来源，实际抓取成功。

## 二、路线结构化解析阶段

### 问题 3：正则字符类写错导致 re.error
- **现象**：`re.split(r"[→->]", text)` 运行时抛出 `PatternError: bad character range →->`，程序崩溃。
- **原因分析**：字符类 `[]` 中 `-` 被解释为**范围符号**，与前后字符组合成非法字符区间（如 `→-`）。
- **解决办法**：改为 `re.split(r"→|->", text)`，用**分支**替代字符类，正确匹配中文箭头与英文 `->`。

### 问题 4：解析前 strip 丢右括号，导致括号子景点无法提取
- **现象**：黄山“天海景观区（鳌鱼峰）”应拆出 `天海` + `鳌鱼峰` 两个景点，但输出只有“天海景观区（鳌鱼峰”一段且括号未拆。
- **原因分析**：先对片段 `strip()` 时把末尾的右括号 `）` 一起去掉，后续正则 `（…）` 无法匹配完整括号对。
- **解决办法**：调整顺序——**先匹配并提取括号内并列子景点，再对主名做 strip**；括号提取用 `[\u4e00-\u9fa5]+` 匹配子景点并用 `、` 拆开（如“清凉台、散花坞”拆为两个）。

### 问题 5：同一景点在不同环节重复出现，导致步骤/层级冗余
- **现象**：
  1. 解析层出现“玉屏楼 → 迎客松 → 玉屏楼”（玉屏楼景观区含迎客松，随后又有玉屏索道下行）；
  2. 张家界“乘天子山索道下山”被同时匹配到两次“天子山”。
- **原因分析**：同一地理区域被多个表述（景区名 + 索道名）命中，未做跨环节去重。
- **解决办法**：
  1. 在步骤列表中做**相邻重复去重**（相邻相同景点只保留第一个），并重排 step_no；
  2. 在时间层级构建时对**同一时段内**的重复景点再去重一次（保留首次出现）。

### 问题 6：景点名粘连活动词，名称归一化不彻底
- **现象**：解析出“北宫门出园”“森林公园门票站进山”“百龙天梯上袁家界”“出沟”等带尾部动作的景点名。
- **原因分析**：路线文本常把景点名与动作连写（如“乘百龙天梯上袁家界”），正则抽取景点后未剥离尾部动词。
- **解决办法**：建立 `TRAILING_VERBS / TRAILING_SEG` 剥离表，循环去掉“景观区 / 索道上行 / 索道下行 / 进山 / 上袁家界 / 出沟 / 出山 / 出发”等尾部词；再经 `NAME_NORMALIZE` 映射（出沟→沟口(出口)、进山→门票站(入口)）得到规范名。

### 问题 7：编号列表与箭头链路格式混淆
- **现象**：颐和园（旧版样本）路线因括号内“邀月门→排云门”被误判为箭头链路；黄山“线路一”含括号但本质是箭头链路。
- **原因分析**：`detect_format` 先判断箭头会把含箭头的编号/括号文本误分类。
- **解决办法**：调整格式识别优先级为 **编号列表 > 箭头链路 > 时间分段**，先匹配 `\d+[.、]` 再匹配 `→`。

## 三、时间层级构建阶段

### 问题 8：箭头/编号路线“景点先于时段说明出现”，时段分桶全部归为上午
- **现象**：黄山（线路一）景点在句首一次性列出、时段说明在句尾，按“字符位置”分桶导致所有景点都归入上午。
- **原因分析**：这类文本的叙述逻辑是“先给整体序列、再给时间安排”，景点字符位置不落在各自时段锚点之后。
- **解决办法**：检测到“景点整体先于第一个时段锚点”时，改用**比例分配策略**——按原文实际出现的时段数量（如上午/中午/下午）对有序景点做均分切分，使层级与文本时间叙述一致。

## 四、运行结果截图与可视化阶段

### 问题 9：终端截图中文乱码 / 缺字
- **现象**：用 Consolas 等宽字体渲染运行日志截图时，大量中文字形缺失（`Glyph missing from font(s) Consolas`），中文全部显示为方块。
- **原因分析**：Consolas 是英文等宽字体，不包含中文字形；matplotlib 不会自动回退到中文字体。
- **解决办法**：改用系统**中文字体（Microsoft YaHei / 微软雅黑）**渲染日志文本，重新生成截图后中文正常显示。

---

## 五、总结

本次实验遇到的 9 个问题覆盖了**反爬对抗、数据源选择、正则陷阱、文本解析边界、名称归一化、格式识别优先级、时段分桶策略、字体渲染**八类场景。核心经验：
1. **官网被反爬 → 转向权威管理机构页面**，兼顾可复现性与来源权威；
2. **解析顺序决定成败**：先识别格式、先提取括号、再 strip，避免正则与字符处理的先后顺序陷阱；
3. **名称归一化要覆盖“粘连词剥离 + 全称/别名映射 + 跨环节去重”三层**，才能得到干净一致的结构化结果；
4. **可视化中文字体需显式指定**，否则缺字影响报告可读性。
