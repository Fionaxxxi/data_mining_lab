# 实验七在线验收：局限 1 与局限 3 的完成情况说明

本文单独记录《实验七报告》7.10 前两项局限的完成程度、已达到的上限、以及为什么单轮全通仍不能等同于“稳定全通”。所有数字取自 `outputs/lab7/online_test_results.json` 与 `outputs/lab7/online_runs/` 的真实运行记录。

## 一、判据

- **在线通过（严格判据）**：意图解析、规划提案、工具决策、最终回答四个阶段都由真实模型提供；任一阶段发生规则回退，该例即失败。
- **零回退**：该例四阶段全部来自真实模型，回退计数为 0。
- 参数校验失败、动作不合法、模型提前停止，均按“回退”处理，不以“结果看起来对”替代判据。

## 五、为达到 12/12 做的收紧（均不改变判据）

1. **决策上下文显式给出下一步**：每轮写入“本轮唯一允许执行的动作是 X”，消除“先 advice 后 route”的顺序型错误。
2. **最终回答格式写死**：回答开头按天/时段列出全部路线地点原文；末尾必须有【材料建议原文】小节，逐条照抄 `condition` 与 `advice`。
3. **天数与问句对齐**：用户未写天数时默认 1 日；模型只能提出与“两天/两日”等词一致的值。
4. **JSON 结构容错**：漏逗号、把数组闭合写成 `}}` 时按结构补 `,`、`]` 后再解析，只修结构不改字段值。
5. **参数位置归一化**：模型把 `scenic` 写在根层时并回 `args`，未知字段仍拒绝。

这些属于计划允许的“安全归一化/提示收紧”，不是规则替代模型，因此相关用例仍按“LLM 决策”记录。

## 六、为什么单轮 12/12 仍不能算“全部解决”

- **模型输出有随机性**：即使 `temperature=0`，3B 在长中文上下文下仍会出现措辞漂移，复跑一例回答漏抄建议。
- **单次决策、不自动重试是既定规则**：一次动作选错或回答不合格式，该例直接失败，没有第二次机会。
- **7B 不是解法**：同样判据下只有 6/12，主要失败是 `day_assignments` 未覆盖全部图谱步骤，且单例耗时约 82 秒；更大模型对严格 JSON 契约的遵从不一定更好。
- **样本仍小**：12 例固定场景不能代表任意输入，错别字、混合意图、多轮改口都未覆盖。

## 七、若要“每次全通”还需什么（未实施）

- 把回答格式校验做成“生成后自检再补写”的两段式（会改变“不自动重试”口径）；
- 对规划提案做更细的结构提示（显式给出步骤数量与 order 范围）；
- 扩大场景集并做多轮重复统计（如每例跑 3 次取通过率），而不是单轮判定；
- 若改用云端更大模型，需先具备真实 API 密钥，且仍需同样的严格判据。

以上都未在本次实施，避免用修改口径换通过率。
