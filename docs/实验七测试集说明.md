# 实验七测试集使用说明

## 测试集概览

这套测试按实验七任务书要求，检查旅游规划 Agent 是否能解析自然语言、按问题类型选择图谱工具、读取结果并生成回答，并在信息不足、未收录景区和服务故障时安全收敛。测试登记共 **63 项**：8 个离线用户场景、47 项自动验收、8 个真实 LLM 在线场景。

默认自动测试强制离线，即使仓库根目录 `.env` 配有真实密钥也不会调用外部服务。真实接口测试必须单独从 CLI 发起，避免整套回归不知情地消耗 API 额度。真实模型回答会有措辞差异，因此自动断言检查结构、约束和来源，不固定整段自然语言。

| 层次 | 数量 | 输入/执行器 | 检查目的 |
|---|---:|---|---|
| 用户场景 | 8 | `data/lab7/scenarios.json`、`src/lab7/tests.py` | 请求、期望意图、路线命中/追问/回退、步骤和建议 |
| 自动验收 | 47 | `src/lab7/check.py` | 图谱与证据完整性、工具契约、按问句选择工具、Observation 闭环、追问/回退、安全边界、离线行为及 LLM 模拟 |
| 真实 LLM 在线场景 | 8 | `src/lab7/online_tests.py` | 用真实模型运行 8 类场景，核对意图、工具动作决策、规划提案、工具证据和最终回答 |

用例编号、来源、执行模式和机器可读的预期结果登记在 [`data/lab7/test_catalog.json`](data/lab7/test_catalog.json)。完整每例结果写入 `outputs/lab7/`。

## 怎么运行

### 运行完整离线回归

从仓库根目录打开 PowerShell：

```powershell
Set-Location 'D:\data_lab\scenic_lab1'
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Lab 7
```

入口按顺序执行 8 个离线场景和 47 项自动验收。实验七的离线脚本强制离线，不读取 `.env` 密钥、不访问网络，也不会产生 API 费用。

也可以分开运行：

```powershell
$py = 'D:\miniconda3\envs\dm_scenic_lab\python.exe'
& $py '.\src\lab7\tests.py'
& $py '.\src\lab7\check.py'
```

`tests.py` 写出场景结果；`check.py` 使用这些结果及图谱文件继续验收。因此单独运行时必须先运行 `tests.py`。

### 完整在线场景测试

确认 `.env` 已配置有效模型后，从仓库根目录执行：

```powershell
Set-Location 'D:\data_lab\scenic_lab1'
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Lab 7 -Online
```

此命令先运行离线 8 场景和 47 项自动验收，再串行向当前配置的真实模型执行 8 个在线场景。它不会自动重试；某例失败也会继续后续用例，最后用退出码和汇总显示整体结果。动态决策会按问题和观察轮次变化请求数；本轮实际尝试 35 次。后续运行次数可能变化，调用可能产生费用。

每个在线案例必须同时满足：

1. 意图解析来源为真实 LLM；
2. 实际请求均有成功响应，失败数和回退数为 0；
3. 有路线的场景中，模型规划提案通过校验，步骤不漏、不重、不乱序且全部来自图谱；
4. 结构化场景断言通过，最终回答非空；未知景区和信息不足案例按预期拒绝编造并如实追问/说明。

模型提出非法计划时，程序会使用规则计划保护用户，但该在线用例仍判失败，不能把安全回退算成模型测试通过。测试结果写入 `outputs/lab7/online_test_results.json` 和 `outputs/lab7/online_test_run.log`；JSON 保留每例完整模型阶段、ReAct 轨迹、工具观察和最终文本，不记录密钥或认证头。

### 手动验证单条真实 LLM 请求

先在仓库根目录 `.env` 配好 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 和 `LLM_TIMEOUT`。密钥留在本机；`.env` 已由 Git 忽略。选用一个图谱已收录且信息充分的请求，然后从仓库根目录执行：

```powershell
$py = 'D:\miniconda3\envs\dm_scenic_lab\python.exe'
& $py '.\src\lab7\cli.py' --query '带老人去黄山玩一天，希望行程轻松平缓' --trace
```

这里不要加 `--offline`。路线场景目前通常访问接口三次：意图解析、图谱约束规划、最终回答；单条请求可消耗最多三次模型请求。成功标准同时满足：

1. 输出显示 `LLM 配置：openai-compatible:<模型名>`；
2. 诊断显示 HTTP 请求 3 次、成功响应 3 次、失败 0 次、回退 0 次；
3. 轨迹中意图解析来源是 `[llm]`，且没有“回退规则版”的 NOTE；
4. 方案仍只使用图谱景点，并保留“当前通行/开放未核验”提示。

只看到 `openai-compatible:<模型名>` 不能算真实调用通过：它表示配置选中了该后端。必须同时检查请求/成功/回退计数。若请求失败，CLI 会显示错误诊断；Agent 会按设计回退到规则结果，此时记为“服务测试失败、系统回退成功”，不能记为 LLM 通过。

#### 历史真实测试记录

在用户明确要求下，实际运行了上述请求。配置模型名 `DeepSeek-V4-pro`：HTTP 请求 2 次、成功 0 次、回退 2 次；两次均返回 `InvalidEndpointOrModel.NotFound`，错误说明模型/endpoint 不存在或当前凭证无访问权限。程序仍生成了方案，但来源是 `offline-rules`。将模型名改为小写 `deepseek-v4-pro` 后重试，结果相同。应用户要求再换成 `Doubao-Seed-2.1-pro`，同样是 2 次请求、成功 0 次、回退 2 次，返回相同错误码；CLI 退出码 0 是因为回退正常完成，不代表模型调用成功。此前尝试官方文档列出的版本化 ID `deepseek-v4-pro-ga-260813`，但该次执行输出未被运行环境完整捕获，故结果记为“未确认”，不计通过。

2026-11-13 补强前曾测试 `kimi-k3`，意图输出不是合法 JSON，最终回答请求又因 `temperature` 参数不受支持而失败；该次历史结果已由后续可用模型完整调用覆盖。

之后尝试把模型名临时改为方舟文档列出的 `deepseek-v4-1-flash-261017`，但只读核对发现当前 `.env` 的 endpoint 实际是阿里云百炼。该请求发往百炼后返回 HTTP 404 `model_not_found`，不能算方舟测试，也不能说明方舟是否可用。测试火山方舟必须将 `OPENAI_BASE_URL` 与 `OPENAI_API_KEY` 配成方舟服务及其凭证，再使用该模型 ID 或方舟控制台分配的 Endpoint ID 重测。

用户随后更新配置，补强前的单条真实调用 2/2 成功。首次调用遇到 socket 被对端关闭时 CLI 曾异常退出；将 `RemoteDisconnected` 纳入网络异常回退后，离线验收通过，真实调用重试成功。

**评分补强后的最新在线结果**见下方“完整在线场景测试结果”及 `outputs/lab7/online_test_results.json`；历史单次冒烟不再代表完整在线测试集结果。此前配置失败记录仍保存在 `outputs/lab7/live_llm_smoke.log`。

## 完整在线场景测试结果

2026-11-13 上一轮行程规划版测试曾 **8/8 通过**，但当时工具选择仍由固定逻辑决定，不能作为动态决策版验收。动态决策版最新完整在线运行有 8 例记录，但 **35 次请求中 23 次成功，15 次工具决策中仅 2 次接受，20 次回退，最终 0/8 通过**。失败包括连接超时/断连、动作参数不符合契约和提前停止。明细见 `outputs/lab7/online_test_results.json`、`online_test_run.log` 与不可覆盖记录 `outputs/lab7/online_runs/20261113_182747.json/.log`。之后针对意图字段类型和动作参数提示做了修正，离线 8/8、47/47 通过；修复后的在线重跑按用户要求中止，不计结果。此前 HTTP 403 权限拒绝运行仍保留为历史记录。

需要验证登录失败、地址错误或模型拒答时，每次只改一种 `.env` 配置，再手动执行同一条 CLI 命令；预期请求失败有记录、错误信息不泄露密钥、系统不崩溃并回退规则。不要用带真实密钥的 `tests.py` 来制造故障；故障场景由本地模拟响应自动覆盖。
