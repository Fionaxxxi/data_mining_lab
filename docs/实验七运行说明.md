# 实验七交付说明（旅游规划 Agent）

实验七采用与其他实验相同的项目目录结构。请从项目根目录运行统一入口，使用项目专用 Conda 环境。事实源为实验六图谱，实验七不重建图谱、不重跑前序实验、不新增抓取。

> 环境说明：`run.ps1` 把解释器固定写为 `D:\miniconda3\envs\dm_scenic_lab\python.exe`，该路径属于项目原机器；本机没有 `D:\miniconda3`，直接调用 `run.ps1` 会报 `Project Python environment missing`。本机复现请用系统 Python 3.13.18 执行下列等价命令（把 `& 'D:\miniconda3\envs\dm_scenic_lab\python.exe'` 换成 `python`）。

实验七直接只读项目已有的 `outputs\lab6\`；不另设实验七文件夹或复制图谱文件。

## 运行方式

### 配置真实 LLM

在仓库根目录编辑 `.env`，填写服务商发放的 `OPENAI_API_KEY`、兼容接口基础地址 `OPENAI_BASE_URL` 和可用模型名 `OPENAI_MODEL`。模板见根目录 `.env.example`；`.env` 已加入 Git 忽略规则，不会随仓库提交。程序启动时自动读取它；当前 PowerShell 会话中已经设置的同名环境变量优先级更高。接口地址填写基础地址（例如 `https://ark.cn-beijing.volces.com/api/v3`），程序会追加 `/chat/completions`。

配置完成后，从仓库根目录发起单次真实模型调用：

```powershell
& 'D:\miniconda3\envs\dm_scenic_lab\python.exe' src\lab7\cli.py --query "带老人去黄山玩一天，希望行程轻松平缓" --trace
```

成功时轨迹会显示配置的 `openai-compatible:<模型名>`、HTTP 请求/成功响应数以及回退数。真实调用通过条件见 [测试集说明](实验七测试集说明.md)；若请求失败，程序会显示错误阶段并回退到规则生成器。

从项目根目录一键复跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Lab 7
```

执行完整在线测试集（先跑离线回归，再真实调用当前配置模型 12 例）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Lab 7 -Online
```

在线测试串行执行、不自动重试；动态决策的请求次数取决于问题和观察轮次，本轮 12 例共尝试 35 次（1.5b）/52 次（3b），后续运行次数可能变化，调用可能产生费用。结果写在 `outputs\lab7\online_test_results.json` 和 `online_test_run.log`。只给 `-Online` 且 Lab 不是 7 会报错；不加 `-Online` 的常规命令不会联网。

也可在仓库根目录运行单个入口：

```powershell
Set-Location 'D:\data_lab\scenic_lab1'
$env:PYTHONUTF8 = '1'
$py = 'D:\miniconda3\envs\dm_scenic_lab\python.exe'

# 单次提问（带 ReAct 轨迹）
& $py src\lab7\cli.py --query "带老人去黄山玩一天，希望行程轻松平缓" --trace

# 交互模式
& $py src\lab7\cli.py --interactive

# 复跑核心验证（check.py 读取 tests.py 更新的结果和已有 SVG 图件）
& $py src\lab7\tests.py
& $py src\lab7\check.py
& $py src\lab7\console_svg.py  # 从真实终端输出文本生成报告用 SVG 摘录
```

核心 Agent、测试和验收仅用标准库。需要重新绘制图件时，在项目虚拟环境安装 `matplotlib` 后运行 `& $py src\lab7\figures.py`；需要重绘两张控制台图片时安装 `Pillow` 后运行 `& $py src\lab7\console_shot.py`。本次环境无法连接包索引，沿用仓库已有 SVG 图件进行验证。根目录 `run.ps1 -Lab 7` 已接入核心测试与验收。

- 自动验收：最新 49/49 通过，退出码 0；LLM 决策和异常路径使用本地模拟，真实模型决策表现以下方在线运行记录为准；
- 在线验收：2026-11-16 本机多轮 12 例。`qwen2.5:3b` 收紧提示后一轮 HTTP 54/54、决策 22/22、**12/12 零回退**，复跑 11/12；`qwen2.5:7b` 为 6/12 且单例约 82 秒。旧版规划链路 8/8 仅作历史记录；
- 引用证据 46 条，缺失 0 条；来源为实验三路线 30 条、实验五建议 16 条；实体查询可另回指实验二原文位置与实验四已审核共指；
- 方案景点全部可回指实验六步骤；同一离线输入两次运行结果一致；
- 图件：三张架构/轨迹/时段 SVG 与两张本次终端输出摘录 SVG 可直接插入报告；仓库的旧 PNG 为历史运行图。

## 已知限制

1. 默认场景回归强制使用 `provider=offline-rules`；完整在线场景由显式 `-Online` 单独执行。本机两轮真实模型均未达到“零回退”，不能标为在线通过。
2. 图谱仅三景区各一条官方整理路线，两日方案是时段切分，不是官方两日线路。
3. 距离、海拔、坡度、索道、时长五类字段在 `data/lab7/route_attributes.json` 中均为 `null`，`route_attr` 会显式列出缺失项；老人/亲子的体力可行性仍无法评估。
4. 实验二/实验四证据已接入实体查询（`lab2_evidence`、`lab4_coref`），但方案正文引用仍只来自实验三路线与实验五建议。
5. 票价、开放时间、通行状态一律不回答，方案末尾均声明“未核验”。
